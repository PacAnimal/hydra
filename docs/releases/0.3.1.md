### Changed

- **Lower input latency over a relay.** Hydra no longer waits for the relay to finish one input message before sending the next, so over a distant Styx the cursor moves smoothly instead of in steps of one round trip. Update Styx along with your machines: this needs a relay from this release, which keeps each machine's messages in order itself. Through an older relay, keystrokes and clicks can arrive out of order.
- Styx also serves the relay at `/relay/parallel`, which runs several of one client's messages at once and keeps no order between them. `RELAY_PARALLEL_INVOCATIONS` sets how many, from 1 to 64 (default 4). Hydra keeps using `/relay`.

### Fixed

- A relay connection logs in once at a time, so the one-second login delay limits it to one login a second, as documented.
