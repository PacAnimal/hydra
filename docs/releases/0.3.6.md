Everything since 0.2.7. Update every machine and your Styx relay together: 0.3 machines don't talk to 0.2 machines, and need a relay from this release. Hydra updates itself; a standalone Styx needs a new image.

### Breaking

- **The embedded relay is encrypted with TLS, and only TLS.** There are no certificates to set up: each relay makes its own on every start, and a machine trusts it only once the relay has proven it knows the password. Machines lose each other until the last one has updated.
- `embeddedStyx.server` must say `https://`, or give no scheme at all. An `http://` address is refused when the config loads.
- `embeddedStyx` pointed at a standalone Styx needs that server on `https://`, behind a certificate your machines already trust.
- **A standalone Styx creates networks only with a signing key.** Start it with `RELAY_SIGNING_KEY` (make one with `docker run --rm ghcr.io/pacanimal/styx:latest keygen`) or `RELAY_SIGNING_PASSPHRASE`, beside `RELAY_PASSWORD`. A relay given only `RELAY_PASSWORD` keeps accepting the configs it already issued, but its web page creates no new ones, and `POST /api/network-config` answers 404.

### New

- **Signed network configs.** New networks get tokens signed with the relay's key, which can be narrowed to a sub-network, to certain hostnames or to an expiry, and revoked with `RELAY_REVOKED_NETWORKS` or `RELAY_REVOKED_IDS`. `styx mint` issues them offline, `styx keygen` makes a key and `styx derive` prints the key a passphrase gives. The [Styx protocol](https://github.com/PacAnimal/hydra/blob/main/Styx.md) shows how to issue them yourself, with reference code in Python, JavaScript, C# and Rust.
- **Edge channel** — `"updateChannel": "edge"` follows prereleases built from the `edge` branch, and moves back onto a stable release once one overtakes them. `styx:edge` is the matching relay image.
- **Middle-click paste on Linux reaches Mac and Windows copies.** A text copy on macOS or Windows lands in both the clipboard and the `PRIMARY` selection on Linux, while between Linux machines the two stay separate.
- Styx also serves the relay at `/relay/parallel`, which runs several of one client's messages at once and keeps no order between them. `RELAY_PARALLEL_INVOCATIONS` sets how many, from 1 to 64 (default 4). Hydra keeps using `/relay`.

### Better

- **Lower input latency over a relay.** Hydra no longer waits for the relay to finish one input message before sending the next, so over a distant Styx the cursor moves smoothly instead of in steps of one round trip.
- A machine that stops reading from the relay (lid shut, Wi-Fi gone) is dropped after 30 s without taking a message, instead of holding up every machine sending to it.

### Fixed

- On a macOS slave, holding a key no longer types an A on every repeat, and holding A in a game no longer lets go of it at the first repeat. The `unicodeKeyRepeat` setting is gone, and ignored if still in `hydra.conf`.
- On Windows, files copied in Explorer stay on the clipboard when the cursor comes back, instead of being replaced by the last clipboard a peer sent.
- A relay address ending in `/` connects instead of failing.
- A relay connection logs in once at a time, so the one-second login delay limits it to one login a second.
